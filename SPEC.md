# smart-endpointing: spec

**One-line goal:** train a turn-detection model that lets a voice agent reply faster without cutting people off. Prove it offline with honest evals, then in a live voice pipeline.

**Headline result to aim for:** "At the same false-interruption rate as a 700 ms silence threshold, the model ends turns N ms sooner (95% CI), on a human-labelled Hindi/Hinglish/English test set and in shadow mode on real calls."

If the model doesn't beat the baseline, that's reported as the result.

---

## 1. The problem

A voice agent decides the user has finished speaking when silence lasts T ms (e.g. 500-800 ms).
- If T is too short, it cuts people off mid-thought ("mera account number hai... [pause] ...4 2 1 5").
- If T is too long, every reply feels slow.

A text model that reads **what was said so far** (is the sentence complete?), combined with **the pause so far** in a policy layer, can reply sooner when the sentence is clearly finished, and wait when it clearly isn't.

## 2. Data

All data has a datasheet in `data/README.md`: source, licence, size, language mix, how labels were made, and known biases.

| Set | Source | Labels | Purpose |
|---|---|---|---|
| **Synthetic train** | An LLM (gpt-4.1-mini) generates customer-support utterances: banking, collections, delivery, telecom. English, Hindi (Devanagari) and Hinglish (Latin script). Many intents and speaking styles: fillers, self-corrections, digits, names. | Complete utterance = END. Prefixes cut at word boundaries = NOT_END. | Training |
| **Hard negatives** | Prefixes ending in connectives and fillers: and, because, so, aur, lekin, ki, matlab, umm, toh, "my number is" | NOT_END | Training + a test slice |
| **Public dialogue text** (optional) | Only permissively licensed task-oriented dialogue corpora; check and record each licence before use | Same truncation scheme | Training (English) |
| **Gold test set** | ~300 prefixes **labelled by me by hand**, never generated by the model under test; balanced across languages and including real pauses from my own recordings | END / NOT_END, human | Final evaluation only |
| **Dev set** | Held-out synthetic data | Auto | Model selection |

Rules:
- Split by **conversation/utterance ID**, never by prefix. Prefixes of one utterance must never appear in both train and test. Add a leakage test for this.
- Deduplicate near-identical utterances before splitting.
- Every dataset gets a manifest with a content hash, so results name the exact data version.

## 3. Model ladder (each must beat the one before to earn its complexity)

| # | Model | Why it's here |
|---|---|---|
| M0 | **Silence threshold** (300 / 500 / 700 / 1000 ms) | The production baseline |
| M1 | **Logistic regression** on hand-made features: last-token class, ends with a connective or filler, length, digit-run state | Classical ML; easy to interpret |
| M2 | **Small transformer trained from random init** on characters/subwords | Training from scratch, written by hand |
| M3 | **A pretrained small multilingual encoder, fine-tuned** (full or LoRA) | Fine-tuning; the expected best accuracy |
| M4 | **Distilled student:** M3-sized or smaller, trained on soft labels from an LLM teacher | Distillation; report teacher-student agreement |

**Pause lives in the policy layer, not in the models.** M1-M4 see text only (plus the agent's question, where the
context ablation uses it) and output P(END | text). The endpointing policy combines that probability with the
silence so far: for example, reply once the pause exceeds a threshold that falls as P(END) rises
("a complete sentence plus 150 ms of silence is probably done"). The same text model can then be paired with
different pause rules without retraining, and the pause distribution in training data cannot leak into the model.

**External baselines** (not trained here, evaluated the same way):
- **LiveKit turn-detector** (text-based end-of-turn model).
- **Pipecat Smart Turn** (audio-based end-of-turn model).
- Before using either, check and record its licence and the current version (pin the exact version/commit).
- Evaluate both on the gold set and in the simulated-conversation eval, and add them to the trade-off plot.

## 4. Evaluation (`evals/`)

**Offline, on the gold set:**
- PR-AUC, F1 at the chosen threshold, precision and recall for END.
- **Calibration:** expected calibration error and a reliability diagram. Probabilities drive a threshold, so they must mean something.
- **Slices:** language (English / Hindi / Hinglish), hard negatives, utterances with digits, short utterances, code-mixed Hindi.
- **LLM-as-judge check:** the teacher LLM's labels vs my labels on the gold set (agreement rate and Cohen's kappa). This shows whether synthetic labels can be trusted.
- **Bootstrap 95% CIs** on every headline number. Model comparisons use a paired bootstrap on the same items.
- **Gold set sizing:** report the 95% CI width for n=300 overall and for each slice next to every gold metric.
  For a proportion near 0.5, n=300 gives about ±5.7 points, a 100-item slice ±9.8 and a 50-item slice ±13.9.
  The eval-set size is set by the precision needed to separate the models, not by how much data is available.

**Simulated conversation eval (the headline):**
- Replay utterances with realistic pause timings (taken from my recordings plus a documented pause distribution).
- For each policy (M0 thresholds; M1-M4 at a range of probability thresholds), measure:
  - **mean and p90 response delay** after the true end of turn;
  - **false-interruption rate:** the share of mid-turn pauses where the agent would have replied.
- Plot the **trade-off curve** for every model, and for the external baselines, against the M0 points.
- **Headline:** the delay saving at an equal false-interruption rate to the 700 ms baseline.

**Online (shadow mode):** see section 6.

## 5. Inference optimisation

- Export the best model to **ONNX**; apply **int8 dynamic quantisation**.
- Report p50/p95 CPU latency, model size, and accuracy change vs fp32 on the gold set.
- Target: **p95 < 10 ms on CPU** for one prediction (it runs at every pause).

## 6. Production integration

- A tiny prediction API: FastAPI locally, and **AWS Lambda** (container or zip with onnxruntime) as the AWS deployment, with measured cold- and warm-start latency.
- Plug into my existing Auvia voice pipeline as a **shadow** endpointer. The live agent keeps the silence threshold; the model's decision is logged at every pause.
- Measure with my **voice-latency-harness**: how often the model would have ended the turn earlier, by how much, and how often it would have interrupted (checked by hand on a sample).
- Only after shadow results look good, a flag to let the model drive endpointing.

## 7. Engineering bar

- Python 3.11, `pyproject.toml` or pinned `requirements.txt`, pytest, CI (GitHub Actions) running the tests on every push.
- Deterministic seeds; every run writes `runs/<id>/config.json` plus a data hash plus metrics; MLflow optional.
- A model card (`MODEL_CARD.md`): intended use, data, metrics by slice, limitations, and when not to use it.
- `DECISIONS.md` and `REPORT.md` written in my own words.
- Secrets only from the environment; never commit `.env`; stage explicit paths only.

### Stage details

**Stage 2 (gold set)**
- `data/GUIDELINE.md`, the labelling guideline, is written by me.
- The labelling CLI supports a third label, **AMBIGUOUS**, alongside END and NOT_END.
- After a week, 50 items are re-labelled blind, and I report intra-annotator Cohen's kappa.

**Stages 3 and 5 (context ablation)**
- Short-reply rows carry the agent's question as `context` (null for other rows). Evaluate each model with and
  without the context as an input, and report the difference overall and on the short-reply and ambiguous slices.

**Stage 4 (M2)**
- I write the training loop myself. Claude only reviews it and points out bugs; it does not write the loop.

**Stage 5 (active learning)**
- Items where the model is uncertain, and items where the model and the teacher disagree, go to a review
  queue in the labelling CLI.
- Report the gain per 100 human labels from this queue vs 100 randomly chosen items.
- Hidden honeypot items (known answers) are mixed into the queue to check labelling quality.

**Stage 7 (implicit labels from shadow logs)**
- **False interruption:** the user speaks within 500 ms of when the model would have replied.
- **Confirmed END:** no user speech within N s of the model's decision point.
- Document the selection bias: the logs are shaped by the current silence-threshold policy, so they only show
  pauses that the live policy let happen.
- An optional 1% randomised-threshold exploration flag, to reduce that bias. It is **off by default**.
